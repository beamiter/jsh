# Bash parity, value pipeline, and startup upgrade

Date: 2026-10-27

Baseline: `7ac5feaab346deaad27a01015e8b190a54ea37e0`

This upgrade closes most of the measurable gap between jsh's Bash mode and
bash 5.2, makes in-process value pipelines safe to interrupt and lazy where
they can be, and removes several startup and hot-path costs. Session snapshot,
bookmark and frecency formats, and the Agent protocol are unchanged.

## How compatibility was measured

Every Bash-mode change was driven by differential probes: small scripts run
under bash 5.2.21 and under jsh, comparing stdout and exit status. At the
baseline, about 300 of the focused probes (arithmetic, builtins, variables,
execution, coreutils-style commands) and 101 of 214 general probes differed
from bash.

The verified probes are committed as a corpus in `tests/data/bash_probes/`
(1,114 scripts in six files) with an opt-in test that runs them on any
machine with bash 5.x:

```sh
cargo test --test bash_differential_tests -- --ignored
```

1,110 match. `known_differences.txt` lists the other four: two deliberate jsh
forms (`let NAME = EXPR` typed bindings and JSON-literal words), FUNCNAME seen
by an EXIT trap after `exit` inside a function, and a SECONDS probe whose bash
result is itself nondeterministic. An always-on test checks that the corpus
parses and that every listed difference names a real probe.

## Behavior changes

### Arithmetic and expansion

- `((...))` and `for ((...))` text is read verbatim up to the matching `))`,
  so `<=`, `>=`, `<<=` and `>>=` are operators, not redirections.
- The evaluator implements bash's pre-expansion of `$var`, `$(...)` and
  nested `$((...))`, `**`, every compound assignment, `base#digits`, octal,
  recursive variable values, array elements as operands and lvalues, and
  bash's sign rules. Nesting is bounded at 1,024 levels with bash's
  "expression recursion level exceeded". `let` is a builtin.
- Brace expansion splits on top-level commas only, so groups nest and keep
  their quoting; invalid sequences stay literal.

### Variables

- One variable model replaces the separate scalar, array and associative maps:
  a global table plus function and temporary scopes with bash's dynamic
  scoping. Functions assign globals unless a name is local; callees see and
  update their callers' locals; prefix assignments live in a temporary scope;
  only exported variables reach child processes.
- Attributes `-i -l -u -c -r -n -x -a -A` are enforced. Indexed arrays are
  sparse; associative arrays list keys in bash's order. Namerefs resolve
  through scopes. RANDOM, SECONDS, EPOCHSECONDS, BASHPID and the other dynamic
  specials work.
- `${...}` supports every bash operator, per element on arrays, plus `@`
  transformations (`@Q`, `@A`, `@a`, `@E`, `@P`, `@U`, ...), slicing and
  indirection. `declare`, `typeset`, `local`, `export`, `readonly` and `unset`
  follow bash, including `declare -p` output that re-evaluates.

### Builtins

- Added getopts, mapfile/readarray, umask, ulimit, times, kill, enable and a
  real `hash` table. `printf` gains `-v`, `%q` and `%(fmt)T`. `read` follows
  bash's field splitting, escapes and options (`-n/-N` count characters, `-d ''`,
  `-a`, `-u`, `-t`).
- `type` (`-t -a -p -P -f`) and `declare -f` print function definitions in
  bash's layout through a new AST printer whose output reparses to the same
  program. `command -v/-V/-p`, `test`/`[`/`[[ ]]` (all file operators, `-v`,
  `-o`, `-R`, arithmetic integer operands, nocasematch), `wait -n`, logical
  `cd`/`pwd`, and `pushd`/`popd`/`dirs` stack numbering match bash.
- Builtins sharing a name with a system program (`sort`, `date`, `split`,
  `uniq`, `sum`, ...) run the installed program unless invoked in jsh's own
  form or fed typed input from a jsh value stage. `command NAME` always runs
  the program and `builtin NAME` the builtin.

### Execution, traps and errors

- Trapped signals have real handlers; their actions run at safe points and
  interrupt `wait`. ERR, DEBUG and RETURN fire with bash's inheritance rules;
  subshells reset traps. LINENO, FUNCNAME, BASH_SOURCE, BASH_LINENO, `caller`,
  BASH_COMMAND and `$_` come from a call stack.
- Added `break`/`continue N`, the `time` reserved word, `{name}` and `N>&M-`
  redirections, bash-style `select`, named coprocesses, `local -` and
  `command_not_found_handle`.
- An error that stops a command (a failed expansion such as `$((1/0))` or
  `${}`, failglob, or a refused assignment such as `R=2` with `R` readonly)
  now skips the rest of its input line and the script continues with the next
  line, `$?` set to 1 and no ERR trap. `eval`, `source` and trap actions
  recover line by line inside their own text; a subshell or command
  substitution exits. `set -e` turns these into an exit except after an
  arithmetic expansion error. `set -u`, `${x:?}` and arithmetic errors in array
  indexes or integer variables end the script; unset-parameter errors exit
  with 127 from a `-c` string and 1 from a script file or standard input, as
  bash's do. Previously every such error ended the whole script, with
  status 1.
- Empty compound bodies (`while do done`, `{ }`, `f() { }`) are syntax errors
  with status 2; `while do done` used to loop forever.
- A signal sent right after a command is forked (`sleep 5 & kill $!`) is no
  longer lost: the shell blocks signals across `fork()` until the child has
  restored default dispositions. Under load the old code lost about one such
  signal in twelve.
- Non-interactive shells no longer print `[1] PID` for background jobs.

### Value pipelines

- Closure `where` and `each` evaluate rows lazily when the input is a stream
  and the body is a pure expression, so `range 0..10000000 | where {...} |
  take 3` stops after three matches. A failing lazy stage reports its error
  instead of yielding a truncated result.
- `from-ndjson --strict` stops at the first malformed line with its line and
  column; the default mode still skips such lines.
- Pipelines honor Ctrl-C and SIGTERM (128+N) instead of running to completion.
  A pipeline whose first command is a source (`range`, `char`, `help`, ...) no
  longer reads the shell's stdin, which used to hang on an idle stdin and
  swallow the input of an enclosing `while read` loop.
- A single scalar result ends with a newline (`range 1..5 | math sum; echo x`
  printed `15x`). `math product` and `math avg` keep integers exact.

### Startup

- Terminal size comes from the TIOCGWINSZ ioctl only. crossterm's fallback ran
  `tput cols` and `tput lines` from PATH on every non-terminal start, two
  process spawns per `jsh -c` and an untrusted PATH lookup.

## Performance

Release builds of the baseline and of this upgrade on the same 4-core Linux
host; medians of 5–30 fresh processes per case. Raw numbers are in
[`performance/upgrade_2026-10-27.json`](performance/upgrade_2026-10-27.json).

| Case | Baseline | Upgraded |
| --- | ---: | ---: |
| Startup (`jsh -c true`) | 5.80 ms | 2.79 ms |
| `for ((...))`, 50k iterations | 98.8 ms | 61.4 ms |
| Assignment in a loop, 50k | 140.6 ms | 78.2 ms |
| `[ ]`-based while loop, 50k | 171.6 ms | 164.4 ms |
| Empty function call, 50k | 139.8 ms | 138.4 ms |
| Function with `local`, 50k | 207.3 ms | 205.0 ms |
| Parameter operators, 5k | 331.5 ms | 32.7 ms |
| `${v// /_}` on 5,000 characters | 14,343 ms | 5.05 ms |
| `range 1..100000 \| where {...} \| math sum` | 23.4 ms, 16.3 MiB | 11.3 ms, 12.2 MiB |
| `range 0..10000000 \| where {...} \| take 3` | 1,550 ms, 792 MiB | 3.7 ms, 12.2 MiB |

The new variable model initially made function calls about 3× slower: every
call and return rewrote FUNCNAME, BASH_SOURCE and BASH_LINENO through the
general array path, which checked the process environment with `getenv`.
Shell-maintained arrays now go straight to the global table and `getenv` is
skipped for names the environment has never held, which brought calls back
to baseline speed.

## Remaining differences

See "Current compatibility boundaries" in the README. The main ones: a
script is parsed whole before it runs, so a syntax error on a late line stops
it before its first line (bash runs the earlier lines); aliases stay enabled
in non-interactive shells; `export -f` and `readonly -f` are accepted but do
not export or protect functions; `$[expr]` is unsupported; a trapped signal
does not interrupt a blocking `read`.
